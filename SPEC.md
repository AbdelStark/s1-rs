### 1.1 Backend adapter

The typed layer talks to a minimal internal trait so either client works:

```rust
pub trait DecisionBackend: Send + Sync {
    type Error: std::error::Error + Send + Sync + 'static;
    fn evaluate(&self, req: WireRequest) -> impl Future<Output = Result<WireResponse, Self::Error>> + Send;
}
// WireRequest / WireResponse: s1-rs owned mirrors of the documented JSON (state, model, questions / model, answers, usage, request_id).
impl<B: typesafe_rs::Backend> DecisionBackend for B { ... }            // feature backend-typesafe-rs (covers Client, LLM backends, Cascade)
impl DecisionBackend for typesafe_ai::ReqwestClient { ... }            // feature backend-typesafe-ai
```

Because `typesafe_rs::Backend` includes LLM backends and `Cascade`, typed question sets work unchanged against Jev, an LLM, or Jev-then-LLM escalation.
**Proc-macro crate:** `syn` 2, `quote`, `proc-macro2`, `darling` for attribute parsing.

MSRV: the minimum stable version supporting edition 2024 (1.85), verified in CI.

## 2. Core traits (crate `s1`)

```rust
/// A type that maps to one System One Choice question.
pub trait ChoiceQuestion: Sized + Copy + Eq + 'static {
    const INSTRUCTIONS: Instructions;           // &'static str or JSON via macro
    const VARIANTS: &'static [Self];
    fn label(self) -> &'static str;              // wire key, stable, snake_case default
    fn description(self) -> Description;         // criteria value
    fn from_label(label: &str) -> Option<Self>;
}

/// Ordered levels. Index order is the wire order of `criteria`.
pub trait ScoreQuestion: Sized + Copy + Eq + Ord + 'static {
    const INSTRUCTIONS: Instructions;
    const LEVELS: &'static [Self];
    fn level_description(self) -> Description;
    fn index(self) -> usize;
    fn from_index(i: usize) -> Option<Self>;
}

/// A struct whose fields are questions. Generated by #[derive(Questions)].
pub trait QuestionSet: Sized {
    type Answers;                                // generated struct of typed answers
    fn questions() -> WireQuestions;            // state filled by caller; see §4
    fn decode(resp: &WireResponse) -> Result<Self::Answers, DecodeError>;
}
```

`Instructions` and `Description` are enums over `&'static str` and a lazily built `serde_json::Value` (for structured criteria, per the advanced-structure docs).

## 3. Derive macros (crate `s1-derive`)

### 3.1 `#[derive(Choice)]`

Input:

```rust
#[derive(Choice, Clone, Copy, PartialEq, Eq, Debug)]
#[s1(instructions = "Which team should handle this ticket?", rename_all = "snake_case")]
enum Department {
    #[s1("Payment or subscription issues")]
    Billing,
    #[s1(label = "tech", desc = "Bugs or integration problems")]
    Technical,
    #[s1(desc_json = r#"{"covers": ["pricing", "plans"], "excludes": ["refunds"]}"#)]
    Sales,
}
```

Rules:
- Only fieldless enums. Compile error with span on any variant with fields.
- 2 to 255 variants (compile error outside range; 255 per TypeSafe launch post, make the bound a single constant).
- Labels unique after renaming; compile error on collision.
- `desc_json` is parsed at compile time with `serde_json` inside the macro; invalid JSON is a compile error.
- Every variant must have a description unless `#[s1(allow_empty_descriptions)]` is set (maps to `null`).

Generated wire fragment:

```json
{
  "type": "choice",
  "instructions": "Which team should handle this ticket?",
  "criteria": {
    "billing": "Payment or subscription issues",
    "tech": "Bugs or integration problems",
    "sales": {"covers": ["pricing", "plans"], "excludes": ["refunds"]}
  }
}
```

### 3.2 `#[derive(Score)]`

- Fieldless enum, declaration order defines level index 0..n.
- Generates `Ord` consistency check: if the user also derives `PartialOrd`, order must match declaration (it does by construction; document).
- Wire: `{"type": "score", "instructions": ..., "criteria": [desc0, desc1, ...]}`.

### 3.3 `#[derive(Questions)]`

```rust
#[derive(Questions)]
#[s1(answers = "TriageAnswers")]                 // optional; default `{Name}Answers`
struct Triage {
    department: Department,                      // ChoiceQuestion
    frustration: Frustration,                    // ScoreQuestion
    #[s1(noul = "The message conveys urgency")]
    urgent: bool,                                // Noul
    #[s1(noul = "Mentions a competitor", true_means = "Names a competing product", false_means = "No competitor named")]
    competitor: bool,
    #[s1(key = "refund_req", noul = "Customer requests a refund")]
    refund: bool,
}
```

Generates:

```rust
pub struct TriageAnswers {
    pub department: ChoiceAnswer<Department>,
    pub frustration: ScoreAnswer<Frustration>,
    pub urgent: NoulAnswer,
    pub competitor: NoulAnswer,
    pub refund: NoulAnswer,
    pub meta: AnswerMeta,          // model, usage, request_id, latency
}
impl QuestionSet for Triage { ... }
```

Rules:
- Field types allowed: any `ChoiceQuestion`, any `ScoreQuestion`, `bool` with `noul` attribute, `Option<T>` of the above (question sent, answer optional on decode for forward compatibility).
- Question key = field name unless `key = ...`.
- Nested `#[s1(flatten)] inner: OtherQuestions` merges question maps; key collisions are compile errors.

### 3.4 Macro testing

- `trybuild` UI tests for every compile error (fields on variants, too many variants, duplicate labels, bad JSON, unsupported field types).
- Golden tests: `serde_json::to_value(Triage::questions())` equals `tests/golden/triage.json` exactly.

## 4. Runtime API

```rust
pub struct S1<C> { client: C, model: Option<String>, tracer: Tracer }

impl<C: DecisionBackend> S1<C> {
    pub fn new(client: C) -> Self;
    pub fn with_model(self, model: impl Into<String>) -> Self;

    /// One state, one question set, one HTTP call.
    pub async fn ask<Q: QuestionSet>(&self, state: impl Serialize) -> Result<Q::Answers, S1Error<C::Error>>;

    /// Many states, same question set. Uses typesafe-rs prepared requests and evaluate_stream when available.
    #[cfg(feature = "pipeline")]
    pub fn ask_many<'a, Q, S, I>(&'a self, states: I, opts: PipelineOpts)
        -> impl Stream<Item = (usize, Result<Q::Answers, S1Error<C::Error>>)> + 'a
    where Q: QuestionSet, S: Serialize + 'a, I: IntoIterator<Item = S> + 'a;
}
```

Blocking mirror `S1Blocking` over `typesafe_rs::BlockingClient` (or `typesafe_ai::UreqClient` with the `backend-typesafe-ai` feature), identical semantics.

`PipelineOpts { concurrency: usize, ordered: bool, stop_on_error: bool }`. Rate limiting and spend caps are configured on the `typesafe-rs` client via its tower layers.

## 5. Answer types

```rust
pub struct ChoiceAnswer<T: ChoiceQuestion> {
    value: T,
    dist: SmallDist<T>,          // array indexed by variant position, f64
    confidence: f64,             // from API
}
impl<T: ChoiceQuestion> ChoiceAnswer<T> {
    pub fn value(&self) -> T;
    pub fn prob(&self, v: T) -> f64;
    pub fn distribution(&self) -> impl Iterator<Item = (T, f64)> + '_;
    pub fn confidence(&self) -> f64;
    pub fn margin(&self) -> f64;                // top1 - top2
    pub fn entropy(&self) -> f64;               // nats, normalized variant available
    pub fn gate(&self, policy: &Policy<T>) -> Verdict<T>;
}

pub struct ScoreAnswer<T: ScoreQuestion> {
    expected: f64,               // API `score`
    dist: Option<SmallDist<T>>,  // per-level probabilities when provided
    confidence: f64,
}
impl<T: ScoreQuestion> ScoreAnswer<T> {
    pub fn expected(&self) -> f64;
    pub fn nearest(&self) -> T;                 // round(expected) clamped
    pub fn at_least(&self, level: T) -> Option<f64>; // P(level >= L), needs dist
    pub fn confidence(&self) -> f64;
    pub fn gate(&self, policy: &Policy<T>) -> Verdict<T>;
}

pub struct NoulAnswer { p: f64 }
impl NoulAnswer {
    pub fn p(&self) -> f64;
    pub fn is_likely(&self) -> bool;            // p >= 0.5
    pub fn gate(&self, policy: &NoulPolicy) -> Verdict<bool>;
}
```

**Decoding rules:**
- Choice: `choice` label must map via `from_label`; else `DecodeError::UnknownLabel { key, label }`. Missing labels in `probabilities` become 0 and increment `meta.normalization_events`. Distribution renormalized if sum deviates by more than 1e-6; original sum kept in meta.
- Score: `score` must be within `[0, n-1]` (tolerance 1e-6); else `DecodeError::OutOfRange`.
- Noul: `noul` within `[0, 1]`.
- Missing answer for a non-`Option` field: `DecodeError::MissingAnswer { key }`.
- Raw `Response` always retrievable through `meta.raw()` for audit.

## 6. Gating

```rust
pub enum Verdict<T> { Act(T), Review(T), Escalate }

pub struct Policy<T> {
    act: f64,
    review: f64,
    per_variant: Vec<(T, f64, f64)>,   // override thresholds for high-risk variants
    signal: Signal,                    // Confidence (default) | TopProb | Margin
}
impl<T: Copy + Eq> Policy<T> {
    pub fn act(threshold: f64) -> Self;
    pub fn review(self, threshold: f64) -> Self;
    pub fn for_variant(self, v: T, act: f64, review: f64) -> Self;
    pub fn using(self, s: Signal) -> Self;
}

pub struct NoulPolicy { yes_act: f64, no_act: f64, review_band: (f64, f64) }
// yes if p >= yes_act; no if p <= no_act; review if inside band; escalate otherwise.
```

Invariants (property-tested): `act >= review`; thresholds in `[0,1]` enforced at construction (`Result`), `Verdict` monotone in the signal.

## 8. Observability

- Span `s1.ask` with fields: `question_set`, `n_questions`, `model`, `request_id`, `latency_ms`, `input_tokens`, `retries`.
- Event per answer: `key`, `verdict`, `confidence` (never the state content by default).
- Metrics (feature `metrics`, via `metrics` crate facade): `s1_request_duration_seconds` histogram, `s1_confidence` histogram per key, `s1_verdict_total{key,verdict}`, `s1_decode_errors_total{kind}`.
- Redaction: state never logged unless `S1::log_state(true)`.

## 9. `s1-test`

```rust
let fake = FakeClient::new()
    .on::<Triage>(|state| Script::new()
        .choice::<Department>(Department::Billing, 0.91)
        .score::<Frustration>(1.2)
        .noul("urgent", 0.97));
let s1 = S1::new(fake);
```

- `Cassette::record(path)` wraps a real client and writes sanitized request and response pairs (API key and configurable state fields removed).
- `Cassette::replay(path)` matches on canonical request JSON hash; mismatch is a test failure with a diff.
- `proptest` strategies: `arb_choice_answer::<T>()`, `arb_calibrated_stream(p_true)` for testing downstream policies statistically.

## 10. `s1-cli`

```bash
s1 ask --state ticket.json --noul urgent="Conveys urgency" --choice dept=@depts.yaml
cat posts.jsonl | s1 map --questions triage.yaml --concurrency 16 --rate 20 > answers.jsonl
s1 gate --key dept --act 0.85 --review 0.6 < answers.jsonl
s1 replay tests/cassettes/triage.json
```

- YAML question files use the same schema as the wire format.
- Exit codes: 0 success, 2 decode error, 3 API error, 4 rate limited after retries.
- Output always JSON Lines with `request_id`.
